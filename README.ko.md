# Anki Card Manager

[ [English](https://github.com/jaewonE/anki-card-manager) | [한국어](https://github.com/jaewonE/anki-card-manager/blob/master/README.ko.md) ]

Anki Card Manager는 `obsidian-to-anki` 마커 블록을 Obsidian 안에서 간결한 접이식 카드로 보여 주고, Vault 전체 카드의 원본 Markdown을 한 화면에서 관리하게 해 주는 확장 프로그램입니다. 버전: **0.3.3**.

## 주요 기능

- Live Preview에서는 카드에서 선택 영역·포커스가 벗어나면 카드 UI를 표시하고, 읽기 화면에서도 카드 UI를 표시합니다. Obsidian 원본 모드에서는 항상 원본 Markdown을 보여 줍니다.
- 카드가 Markdown 코드 펜스의 유일한 내용이면 바깥 펜스까지 UI로 대체해 빈 펜스가 남지 않게 하며, 해당 카드를 삭제할 때도 전용 펜스를 함께 제거합니다.
- 질문은 항상 표시하고 답변은 접이식 영역에 둡니다. 원형 연필 아이콘(**Edit source**)을 누르면 원문 블록이 나타나고 커서가 이동합니다. 문서 하단 모음에서도 동일하게 사용할 수 있으며, 카드 유형은 답변 상단에 표시합니다.
- 막대한 양의 카드가 있는 노트에서는 연속 묶음을 24장 단위 렌더링 청크로 나누고 선택·포커스 변경 시 파싱 결과를 재사용합니다. 답변 Markdown과 조작 버튼은 카드를 처음 펼칠 때 생성합니다. 읽기 화면은 화면 가까이에 있는 청크를 우선 렌더링하고 나머지는 제한된 백그라운드 배치로 채워 최하단 직접 이동도 안정적으로 처리합니다.
- 질문 전체를 표시하는 것이 기본값입니다. 한 줄 말줄임 설정을 켜도 접힌 카드에만 적용하며, 펼치면 질문 전체를 표시합니다.
- Cloze에는 제공된 Material Symbols Light 형광펜 아이콘, 나머지 유형에는 Anki 형태의 카드·별 아이콘을 사용합니다. 등록 상태에 따라 파란색/붉은색으로 표시하며, 어두운 테마에서는 더 밝은 색을 사용합니다.
- 전체 가장자리에 작은 그림자(흐림 4px)를 두고, 좌우 6px 여백으로 잘림을 방지합니다. 어두운 테마에서는 흰색 그림자를 사용합니다. 공백만 사이에 있는 연속 카드는 하나의 그림자로 묶고, 내부 카드는 개별 그림자나 둥근 모서리 없이 얇은 구분선으로 나눕니다. 문서 하단 모음도 같은 형태이며, 연필 편집 버튼에는 그림자를 두지 않습니다.
- 답변 상단에 카드 유형 플로팅 메뉴와 색상으로 구분되는 Registered/Unregistered 토글을 제공합니다. 편집기의 기본 실행 취소·저장 흐름으로 원문에 반영합니다.
- 기본값은 원래 위치 유지입니다. 이중 확인을 거친 하단 모으기는 전체 Vault의 카드 원문을 각 노트 하단의 각주 위로 실제 이동하며, 백업과 복구 기능을 제공합니다.
- 한 줄에 `<START_ANKI>`를 입력하면 설정된 카드 유형, 질문·답변용 빈 줄, 해당 구분자와 `<END_ANKI>`를 자동으로 완성합니다. 입력 또는 Enter 시 다음 시작 마커보다 먼저 닫는 마커가 있으면 중복 완성하지 않으며, 인라인으로 적힌 다음 시작 마커도 구분합니다.
- 카드 묶음 바로 아래에서 Backspace 또는 위쪽 방향키를 누르면 마지막 카드의 종료 마커 끝으로 진입해 원문을 편집합니다. 앞쪽 Delete도 보호하며, 일반 텍스트 편집과 명시적 선택 영역 삭제는 그대로 가능합니다.
- `Cloze` 유형과 `Text:` 구분자를 지원합니다. 빈칸별 독립 공개, 전체 공개/비공개 토글, 답변을 닫을 때 모두 가리기를 제공합니다.
- 자동완성 시 `anki_deck: Inbox`와 `anki_tags: [Inbox]`가 YAML에 없으면 추가합니다. 이 기본값은 설정에서 바꿀 수 있습니다.
- 등록 및 등록 해제 카드의 로컬 IndexedDB 색인을 유지합니다. 다시 열 때 저장된 색인을 즉시 표시하고 파일 메타데이터를 비교하여 생성·수정·이름 변경·삭제된 Markdown만 다시 파싱합니다.
- 표에서 원본 위치 열기, 수정, 삭제를 수행하면 해당 Markdown 원문에 직접 반영합니다.
- Anki와 통신하지 않고 등록 상태를 전환합니다. 등록 해제 시 독립된 `<!--ID: ... -->` 줄을 제거하고 마커를 `<ANKI_START>` / `<ANKI_END>`로 바꾸며, 등록 시 원래 마커로 되돌립니다.
- Type과 Deck 열을 분리하고, `::` 기준 덱 계층과 각 덱 내부의 평면 태그 그룹을 제공합니다.
- 검색 포커스와 커서를 유지하며 대소문자·공백 차이에 유연한 속성 검색, `tag:t1,t2` 형태의 쉼표 목록, `-tag:t1,t2` 형태의 제외 검색, 포함 조건에 적용되는 색상 구분 AND/OR 버튼(기본 AND)을 제공합니다.
- 행·표·그룹 체크박스로 등록 전환, 태그·덱 변경, 삭제를 일괄 수행하며 변경 범위를 확인한 후 적용합니다.
- 네 가지 카드 트리거를 설정할 수 있습니다. 별도의 전체 Vault 저장·적용 버튼을 눌러야 반영되며 원문 백업과 복구 기능을 제공합니다.
- Search/Filter, Grouping, Change state 영역을 구분하고, 실제 카드 유형 필터와 제공된 필터 초기화·파일 동기화 아이콘을 사용합니다. Actions 열 없이 질문을 클릭해 편집 창을 엽니다.
- 기존 Question, Answer, Type, Deck, Tags, Source, Status 열을 모두 유지하면서 표 한 페이지에는 최대 100행만 렌더링합니다. 평면 검색 결과의 페이지 이동 UI는 전체 선택 도구 모음 오른쪽 끝과 표 아래에 함께 표시되며, 페이지를 이동하면 관리 화면 최상단으로 돌아갑니다. 큰 접힌 그룹의 내부 표는 그룹을 열 때 생성합니다.
- 선택한 고유 카드를 Count/Rate와 실행 시각 기반 시드로 매번 새롭게 샘플링합니다. 그룹별 할당을 지정할 수 있으며 오류 시 기존 선택을 유지합니다.
- 상단 Sync 아이콘이나 명령 팔레트에서 확인을 받은 뒤에만 전체 로컬 카드 색인을 재구축하고, 원문은 건드리지 않은 채 파일 수 기준 진행률을 표시합니다. 성공하면 확인 버튼을 파란색 **Done**으로 바꾸고, 실패하면 재구축 직전의 전체 색인을 복구한 사실을 붉은색 문구로 명확히 표시합니다.

## 카드 형식

기본 트리거를 사용할 때 다음 등록 형식을 인식합니다.

```text
<START_ANKI>
Obsidian-Basic
질문(여러 줄 가능)
Back:
답변(여러 줄 가능)
<!--ID: 1775887365861-->
<END_ANKI>
```

카드가 들어 있는 Markdown 파일에는 다음 YAML 속성이 있어야 합니다.

```yaml
---
anki_deck: 개발::정처기
anki_tags:
  - 정처기
---
```

이 플러그인은 `obsidian-to-anki` 형식과 호환되지만 Anki, AnkiConnect 또는 `obsidian-to-anki` 동기화 작업을 직접 실행하지는 않습니다.

### Cloze 카드

카드 유형이 정확히 `Cloze`일 때만 `Back:` 대신 `Text:`를 사용합니다.

```text
<START_ANKI>
Cloze
**UML**이란 무엇인가?
Text:
**UML**은 {{c1::표준화된 객체 지향 모델링 언어}}이다.
- 구성요소: {{c1::사물}}, {{c1::관계}}, {{c2::다이어그램}}
<END_ANKI>
```

각 빈칸에는 불투명한 형광펜 형태의 가리개가 표시됩니다. 같은 번호를 가진 빈칸도 클릭하거나 포커스를 두고 Enter/Space를 누르면 개별적으로 공개됩니다. 카드 유형 옆의 **Reveal all answers / Hide all answers**로 전체를 전환하며, 답변을 닫으면 모두 다시 가려집니다. 공개한 답변에서는 굵은 글씨와 인라인 코드 등 Markdown 서식이 유지됩니다.

제공된 예시의 단일 콜론 형식 `{{c1:답변}}`도 표시할 수 있으나 보기만으로 원문 표기를 바꾸지는 않습니다. Anki 호환성을 위해서는 표준 이중 콜론 형식 `{{c1::답변}}`을 사용하십시오. 등록 전환과 일반 편집은 `Text:`를 유지합니다. 카드를 보거나 빈칸을 공개하는 동작은 노트를 수정하지 않습니다.

### 유형·등록 상태 변경

카드를 펼치고 아래쪽 삼각형이 붙은 유형 이름을 누르면 Obsidian 기본 플로팅 메뉴에서 **Obsidian-Basic**과 **Cloze**를 선택할 수 있습니다. 키보드 선택도 지원합니다. Cloze에서 Basic으로 바꾸면 `Text:`를 `Back:`으로 바꾸고, 질문·답변의 단일/이중 콜론 빈칸 표기를 답변 텍스트로 풀어냅니다. Markdown 서식은 유지하고 힌트는 제거합니다. Basic에서 Cloze로 바꿀 때는 유형과 구분자(`Text:`)만 변경하며 빈칸을 자동으로 만들지 않습니다. 유형을 바꿀 때 ID와 등록 상태는 유지합니다.

유형 옆의 **Registered** 또는 **Unregistered** 버튼을 누르면 등록 상태가 전환됩니다. 카드 아이콘과 동일하게 등록은 파란색, 미등록은 붉은색이며, 어두운 테마에서는 더 밝은 색을 사용합니다. 마우스를 올리거나 키보드로 포커스해도 해당 색상을 유지합니다. 등록 해제 시 독립된 ID 줄을 제거하고 설정된 비활성 트리거로 바꾸며, 재등록 시 활성 트리거를 복원하되 ID를 생성하지는 않습니다. Live Preview에서는 펼침을 유지하고 편집기의 실행 취소·저장을 사용합니다. 읽기 화면의 버튼은 원본 파일을 수정한 뒤 화면을 갱신합니다. 이 상태는 Markdown 마커 기준이며 Anki에 실제 노트가 존재하는지 여부를 뜻하지 않습니다.

## 사용 방법

1. 독립된 줄에 `<START_ANKI>` 또는 설정한 등록 카드 시작 트리거를 입력합니다. 다음 시작 마커 전에 대응하는 닫는 마커가 없다면 나머지 카드 템플릿과 누락된 YAML 속성이 즉시 추가됩니다.
2. 질문과 답변을 작성한 뒤 편집기 선택 영역을 마커 블록 밖으로 옮기거나 다른 패널로 포커스를 이동해 접이식 카드를 확인합니다. **Edit source**를 누르면 원문으로 돌아갑니다.
3. 왼쪽 리본의 라이브러리 아이콘을 선택하거나 **Anki Card Manager: Open card manager** 명령을 실행합니다. 저장된 카드 색인을 즉시 표시하고 변경된 Markdown을 백그라운드에서 맞춥니다.
4. 검색, 상태·유형 필터, 덱·태그 그룹을 사용하고 질문을 클릭해 편집하거나 원문을 엽니다. 여러 카드를 선택해 샘플링 또는 일괄 관리합니다.

관리 화면의 수정과 삭제는 Vault 원문을 직접 변경합니다. 특히 여러 카드를 정리하기 전에는 평소 사용하는 백업이나 버전 관리를 유지하십시오. 스캔 후 파일 내용이 달라졌다면 오래된 범위에 쓰지 않고 작업을 중단하므로, 다시 스캔한 뒤 재시도하면 됩니다.

### 덱·태그와 관리 화면

`anki_deck`은 같은 노트의 모든 카드가 공유하는 단일 문자열입니다. `Mother::Child`는 Mother 아래 Child 덱 소속을 뜻하며, 하나의 카드가 상위 덱들에 중복 소속되는 것은 아닙니다. `anki_tags`는 독립적인 문자열의 목록이며, 각 카드는 같은 노트의 태그들을 모두 가집니다. 태그에 `/` 또는 `::`가 포함되어도 덱 계층으로 나누지 않고 하나의 태그명으로 표시합니다.

초기 화면은 평면 표입니다. **Group by deck hierarchy**와 **Group by tag**를 각각 켤 수 있고, 둘 다 켜면 덱 계층을 먼저 구성한 다음 각 카드가 직접 소속된 덱 안에서 태그별로 나눕니다. **Deck: Inbox (7)**, **Tag: Inbox (7)**처럼 그룹 종류를 함께 표시합니다. 다중 태그 카드는 여러 그룹에 나타나지만 카드 수와 선택은 중복 계산하지 않습니다. 그룹 체크박스는 접힌 하위 그룹까지 포함한 검색 결과를 선택·해제하고, 일부만 선택되면 중간 상태로 표시합니다. 필터 변경으로 검색 결과에서 제외되는 카드의 선택은 해제됩니다. 각 표 페이지는 기존 일곱 데이터 열을 유지하면서 최대 100행만 표시합니다. 평면 검색 결과가 여러 페이지이면 동일한 Previous/Next UI를 전체 선택 도구 모음의 오른쪽 끝과 표 아래에 모두 표시하며, 어느 쪽에서 페이지를 이동해도 관리 화면 최상단으로 돌아갑니다. 100개가 넘는 카드가 있는 그룹은 접힌 상태로 시작하며 열기 전에는 숨은 표를 만들지 않습니다. 펼친 그룹은 각각 Previous/Next 페이지를 가집니다.

전체 선택 체크박스는 **Select all matching cards** 문구 왼쪽에, 그룹 버튼은 문구 바로 뒤에 배치하며 도구 모음 전체를 왼쪽 정렬하고 왼쪽 여백 12px을 둡니다. 그룹 버튼은 그룹핑을 켜고 검색 결과가 있을 때만 표시됩니다. 하위 그룹을 포함해 하나라도 열려 있으면 **전체 접기**, 모두 닫혀 있으면 **전체 펼치기** 버튼이 표시됩니다.

중첩 그룹을 포함한 모든 표는 화면 폭과 관계없이 열과 머리글을 유지합니다. 좁은 화면이나 패널에서도 Key-Value 목록으로 바꾸지 않고 각 표 안에서 가로 스크롤합니다. 표의 스크롤 영역에 키보드 포커스를 두고 좌우 방향키로 이동할 수도 있습니다. 화면 읽기 프로그램용 이름은 유지하되 표 전체에 마우스를 올렸을 때 툴팁으로 표시하지 않습니다.

**Search/Filter**에는 검색창, 바로 오른쪽의 **AND/OR** 버튼, **All statuses / All card types** 드롭다운이 있습니다. AND는 파란색, OR는 주황색이며 다크 모드에서는 더 밝게 표시합니다. 드롭다운은 선택된 텍스트에 맞는 폭을 사용하고 검색창이 남은 폭을 차지합니다. 유형 선택지는 현재 Vault에서 발견한 카드 유형입니다. **Grouping**은 연한 파란색 패널과 파란 활성 버튼, **Change state | N selected**는 연보라색 패널과 활성 버튼, **Sampling**은 연한 초록색 패널을 사용합니다. 세 영역의 제목 글자 크기는 같습니다. 검색 결과/전체 카드 수는 최상단에서만 표시합니다.

Question과 Source 링크에는 동일한 내부 여백과 밝은 배경, 살짝 둥근 모서리를 적용합니다. Hover/Focus 시에도 일반 글자색을 유지하고 밑줄을 표시하지 않으며, 키보드 포커스 표시는 유지합니다. 질문을 클릭하면 **Edit Anki card**가 열립니다. 유형 드롭다운은 `Obsidian-Basic`과 `Cloze`를 제공하며, 저장 시 개별 카드와 같은 Cloze→Basic 변환을 사용합니다. 원본 위치를 클릭하면 해당 카드 위치의 편집 화면으로 이동하고, 저장하지 않은 입력은 버린 뒤 창을 닫습니다. 취소하면 원문을 바꾸지 않습니다. 등록 전환·삭제는 Actions 열 대신 일괄 작업 영역에서 수행합니다.

**Reset** 아이콘(`carbon--filter-reset.svg`)은 검색어, 상태·유형 필터, 그룹핑, 펼침 상태, 페이지, 샘플링 설정과 선택을 초기화합니다. 그 옆의 **Sync** 아이콘(`ant-design--file-sync-outlined.svg`)은 사용자가 직접 실행하는 전체 색인 재구축입니다. 모든 Markdown을 다시 파싱한다는 확인 창을 먼저 띄우고, 승인하면 완료/전체 파일 수를 progress bar로 표시합니다. 성공하면 **Rebuild all Markdown files** 버튼이 파란색 **Done**으로 바뀌며, 이를 누르면 창이 닫힙니다. 파일 하나라도 재구축하지 못하면 저장 색인과 메모리 색인을 모두 재구축 직전의 완전한 스냅샷으로 되돌립니다. 확인 창은 복구 사실과 오류를 붉은색 문구로 표시하고 다시 시도하거나 닫을 수 있게 합니다. 명령 팔레트의 **Rebuild card index**도 같은 창을 엽니다. 두 경로 모두 Markdown 원문이나 Anki를 변경하지 않습니다. 시작 시 대조와 Vault의 생성·수정·이름 변경·삭제 이벤트는 계속 변경된 파일만 증분 처리합니다. 필터에 지정한 유형이 더 이상 존재하지 않으면 All card types로 돌아갑니다.

### 검색 문법

검색은 대소문자와 값 내부의 공백 차이를 무시하며 부분 문자열로 비교합니다. 단, `status`는 `registered` 또는 `unregistered`와 정확히 일치해야 합니다. 검색창 바로 오른쪽 버튼으로 **포함 조건**의 결합을 AND(기본값, 모두 일치) 또는 OR(하나라도 일치)로 바꿉니다. 쉼표 값뿐 아니라 나열한 속성·일반 단어에도 같은 결합 방식을 적용하며, 제외 조건은 두 모드 모두에서 결과를 추가로 좁힙니다.

```text
tags:Inbox
tag:Inbox,Math
TAGS : in box
deck:Mother::Child type:Cloze
tags:"Study notes" path:software
-tag:t1,t2
deck:Mother::Child -type:Cloze -path:Archive
```

지원 속성: `deck` / `anki_deck`, `tags` / `tag` / `anki_tags`, `type`, `front` / `question`, `back` / `answer`, `path` / `source`, `status`, `id`. 덱·태그·유형 값은 쉼표로 나눕니다(이름에는 쉼표를 사용할 수 없음). `tag:t1,t2`는 어느 모드에서든 `tag:t1 tag:t2`와 같고, OR는 서로 다른 속성 사이에도 적용됩니다. 속성 값은 다음 속성 앞까지 이어지며, 따옴표는 속성처럼 보이는 텍스트를 보호합니다. 첫 속성 앞 일반 단어는 질문·답변·유형·덱·태그·경로·ID에서 같은 결합 방식으로 검색합니다. 상태·유형 드롭다운은 항상 검색 결과를 추가로 좁히며, 빈 검색창은 두 필터에 맞는 모든 카드를 보여 줍니다. Reset은 AND로 돌아갑니다.

지원 속성 바로 앞에 `-`를 붙이면 해당 값에 일치하는 카드를 제외합니다. `-tag:t1,t2`와 `-tag:t1 -tag:t2`는 동일하며, OR 모드에서도 **둘 중 하나라도** 일치하는 카드를 제외합니다. 여러 제외 조건은 항상 함께 적용되고, 포함 조건에 일치해도 제외된 카드가 다시 나타나지 않습니다. 제외 조건만 입력하면 다른 필터에 맞는 카드 중 제외 대상이 아닌 카드가 모두 표시됩니다. 대소문자·공백·부분 일치 규칙과 쉼표 지원 범위는 포함 검색과 같으며, 입력 중 값이 비어 있는 조건은 무시합니다. `front:"literal -tag:t1"`처럼 따옴표 안의 속성 모양 문구는 문자 그대로 검색합니다. 지원 속성이 없는 `-word`는 제외 조건이 아닌 일반 텍스트입니다. 검색으로 원문이나 등록 상태를 변경하지 않습니다.

### 일괄 변경과 파일 단위 YAML

행 또는 그룹을 선택한 뒤 **Register**, **Unregister**, **Change tags**, **Change deck**, **Delete**를 선택합니다. 모든 작업은 확인 후 실행합니다. 등록 전환과 삭제는 선택한 고유 블록에만 적용하고, 등록 해제는 독립 ID 줄을 제거하며 삭제는 카드 전용 코드 펜스도 함께 제거합니다. Anki 앱에 이미 존재하는 노트를 삭제하지는 않습니다.

**덱·태그 변경은 YAML이 속한 파일의 모든 카드에 적용되므로 선택하지 않은 카드도 함께 변경됩니다.** 확인 창에 대상 파일 목록, 전체 영향 카드 수와 미선택 카드 수를 명시합니다. 카드 위치를 옮기거나 카드별 별도 속성을 만들지 않습니다. 덱은 하나의 이름을 입력하고, 태그는 한 줄에 하나씩 추가·제거·교체할 수 있습니다. 교체 시 빈 입력은 태그 목록을 비우며, 중복 태그는 제거합니다. 태그 제거는 대소문자를 구분해 정확히 일치하는 값을 제거합니다. 다른 YAML 속성과 Markdown 본문은 보존하지만 YAML 서식·주석은 정규화될 수 있습니다.

일괄 작업은 열린 편집기를 저장하고 모든 대상을 사전 검사한 후 파일별로 한 번씩 씁니다. 카드 목록이나 메타데이터가 바뀌면 오래된 작업을 중단하고, 각 쓰기 직전 원문도 원자적으로 비교합니다. Vault는 여러 파일을 하나의 트랜잭션으로 쓰지 않으므로 중간 실패 시 나머지 작업을 멈추고 완료한 파일 경로를 안내합니다. 최신 사용자 편집을 덮어쓸 수 있는 자동 롤백은 하지 않습니다. 백업이나 Obsidian File Recovery로 이전 내용을 복구할 수 있습니다. YAML 오류 등으로 읽지 못한 파일은 건너뛰고 관리 화면 상단에 개수를 표시합니다.

### 선택 카드 샘플링

Change state 아래에서 **Sampling**을 켜고 **Count** 또는 **Rate**와 값을 입력한 뒤 **Execute**를 누릅니다. 기본값은 비활성화, Rate **30%**입니다. 추출한 카드만 선택 상태로 남기고 나머지는 선택 해제하며 카드 원문·등록 상태·파일은 수정하지 않습니다. 실행할 때마다 현재 시각을 랜덤 시드로 사용하므로 같은 후보와 설정에서도 다른 카드가 뽑힐 수 있습니다. 안정적인 카드 정렬은 Vault 스캔 순서와 중복 태그 행이 후보군에 편향을 만들지 않도록 유지합니다.

- Count는 선택한 고유 카드 수 이하의 양의 정수여야 합니다.
- Rate는 0 초과 100 이하이며, 전체 추출 수는 `ceil(선택 수 × 비율 / 100)`로 올림합니다.
- 각 그룹명 옆의 **Sampling: Count/Rate + 값**으로 전체 표본의 일부를 해당 그룹에 배정합니다. 모든 그룹은 전체 샘플링 기준과 독립적인 공통 기준을 가지며, 한 그룹에서 바꾸면 모든 그룹이 함께 바뀝니다. 하위 그룹을 포함한 선택 카드만 대상입니다. 빈 입력은 미지정이고 명시적 0은 해당 그룹을 나머지 후보에서도 제외합니다. 그룹 Count는 0 이상의 정수이며 합계가 최종 추출 수를 넘을 수 없습니다. 그룹 Rate는 최종 표본의 배분 비율(0–100%)이며 합계가 100%를 넘을 수 없습니다.
- 예: Count 10에서 A 그룹에 6을 지정하면 A에서 6개, A 밖에서 4개를 뽑습니다. 100개 선택 후 Rate 30, A에 50%를 지정하면 A에서 15개, A 밖에서 15개를 뽑습니다. 비율을 정수로 바꿀 때는 미지정 몫도 포함해 소수 부분이 큰 순서로 남는 개수를 배분하여 전체 목표 수를 맞춥니다.
- 독립 기준 예: 전체 Count 10에 그룹 Rate 30%, 40%, 30%를 지정하면 서로 겹치지 않고 후보가 충분한 그룹에서 3, 4, 3개를 뽑습니다. 전체 Rate에 그룹 Count를 지정하는 반대 조합도 가능합니다.
- 그룹 후보가 부족하면 가능한 선택 카드를 모두 뽑고 부족분은 나머지 후보에서 채웁니다. 태그 중복이나 부모·자식 그룹에서도 한 카드를 두 몫으로 계산하지 않습니다. 선택 후보가 적은 그룹부터 처리하며 동률이면 고정된 그룹 키 순서를 사용합니다. 따라서 중복 그룹에 표시되는 선택 수에는 다른 그룹 몫으로 뽑힌 카드가 포함될 수 있습니다.
- 나머지 표본은 **값을 지정한 모든 그룹의 바깥에 있는 선택된 고유 카드**에서 뽑습니다. 추출 후 목표 수를 채울 후보가 부족하면 오류를 표시하고 원래 선택을 그대로 둡니다. 전체 수를 줄이거나 그룹 값을 조정·삭제하십시오. 지정 그룹 안에 남은 카드를 나머지 몫으로 자동 사용하지는 않습니다.

**그룹 공통** Count/Rate나 그룹핑을 바꾸면 그룹별 할당을 초기화합니다. **전체** 기준을 바꿀 때는 그룹 기준과 값을 유지합니다. 필터로 사라진 그룹의 할당은 제거합니다. Reset은 전체 샘플링 비활성화·Rate 30%, 그룹 Rate·빈 값으로 되돌립니다. 샘플링 설정은 현재 관리 화면에만 유지하며 영구 저장하지 않습니다.

## 설정

- **Card placement:** Keep in place(기본값) 또는 이중 확인을 거치는 전체 Vault 원문 하단 이동입니다. **Collect cards again**으로 이후 추가한 카드를 다시 모읍니다.
- **Single-line titles:** 접힌 카드에만 한 줄 말줄임을 적용합니다. 기본값은 꺼짐입니다.
- **Complete start markers:** 카드 자동완성을 켜거나 끕니다.
- **New card defaults:** 카드 유형 드롭다운(`Obsidian-Basic` 또는 `Cloze`, 기본값 `Obsidian-Basic`), 덱(`Inbox`), 태그(`Inbox`) 기본값입니다.
- **Card triggers:** 등록 카드의 시작·종료, 등록 해제 카드의 시작·종료 트리거입니다. 기본값은 각각 `<START_ANKI>`, `<END_ANKI>`, `<ANKI_START>`, `<ANKI_END>`입니다.

### 원문을 문서 하단으로 모으기

**Collect at document end**를 선택하면 경고 창이 열립니다. 확인 체크박스를 선택해야 **Move all cards** 버튼을 누를 수 있으며, 취소하면 아무것도 바꾸지 않습니다. 확인 후 열린 편집기를 저장하고 모든 Markdown의 변경 계획을 만든 다음, 쓰기 전에 전체 변경 전·후 백업을 검증합니다. 사용자 지정 트리거의 등록·미등록 카드를 모두 옮기며 카드 내용·ID·순서·YAML·줄바꿈 형식을 보존합니다. 원래 위치에 남는 빈 줄만 한 번의 줄바꿈으로 줄입니다. 코드 펜스 밖의 첫 최상위 각주 정의 앞에 카드를 넣으며, 각주 정의 이후 내용은 그대로 둡니다. 각주가 없으면 파일 끝에 넣습니다.

화면 배치만이 아닌 실제 원문 변경입니다. Keep in place로 돌아가도 이전 위치를 자동 복원하지 않습니다. 두 설정 모두 실제 위치에서 렌더링하며, 입력·렌더링·시작·설치 시에는 원문을 옮기지 않습니다. 새 카드에는 **Collect cards again**을 사용하십시오. 이전 가상 하단 모음 설정으로 업데이트한 경우에도 새 확인이 필요하며, 확인 전에는 Keep in place를 사용합니다.

백업은 `<configDir>/plugins/anki-card-manager/placement-migration.json`에 기록하고 완료·복구 후 `placement-backups/`에 보관합니다. 쓰기 직전 원문을 비교하고, 실패하면 다른 편집이 없는 변경 파일만 복구합니다. 동시 편집·누락 파일은 덮어쓰지 않고 **Recover card placement**가 끝날 때까지 자동화를 중지합니다. 고유한 완료 표식으로 반복 수집의 중단 여부까지 구분하므로 완료 후 새 편집을 되돌리지 않습니다. 별도 백업을 유지하고 이동 중 편집을 피하십시오. 백업 JSON에는 개인 노트 내용이 들어가며 자동 삭제하지 않습니다.

### 트리거 저장과 전체 Vault 치환

트리거 입력값은 임시 상태이며 입력만으로 저장하거나 렌더링·자동완성을 바꾸지 않습니다. 적용하지 않고 설정을 닫으면 임시 입력을 버립니다. **저장 및 전체 Vault에 적용**을 누르면 네 값을 함께 적용합니다. 각 값은 비어 있지 않은 한 줄 문자열이어야 하고 앞뒤 공백이 없어야 합니다. 네 값은 서로 달라야 하며 다른 값을 포함해서도 안 됩니다.

이 버튼은 현재 저장된 네 트리거가 등장하는 **전체 Vault Markdown의 모든 위치**를 문자 그대로 치환합니다. 정상 카드뿐 아니라 일반 문장, 코드 예시, YAML도 포함됩니다. 동시에 치환하므로 트리거끼리 값을 맞바꿔도 연쇄 치환되지 않고, 정규식 문자나 `$`도 일반 문자로 취급합니다. 바이너리 파일은 제외합니다. 모든 파일 쓰기가 성공하면 렌더링, 자동완성, 원문 편집, 등록 전환, 삭제 보호, 관리 화면 스캔에 새 값이 적용됩니다. **`obsidian-to-anki`의 설정은 자동으로 바꾸지 않으므로 해당 플러그인에서도 트리거를 별도로 맞춰야 합니다.**

별도 백업을 유지하고 치환 중에는 노트 편집을 피하십시오. 열린 노트 편집기를 먼저 저장하고, Markdown을 쓰기 전에 `<configDir>/plugins/anki-card-manager/trigger-migration.json`에 전체 변경 전·후 원문을 백업하고 검증합니다. 각 쓰기 직전에도 원문을 비교합니다. 설정 저장 전에 실패하면 다른 편집이 없는 변경 파일만 백업으로 복원하며, 동시에 편집했거나 사라진 파일은 덮어쓰지 않습니다. 미완료 작업이 있으면 Obsidian을 재시작해도 카드 자동화가 일시 중지됩니다. 설정의 **Recover trigger migration**을 사용하고, 충돌 파일 안내가 나오면 백업에서 해당 파일을 직접 복원한 뒤 다시 시도하십시오. 설정 저장까지 끝난 작업은 후속 편집을 덮어쓰지 않고 백업 보관만 마무리합니다.

성공하거나 복원된 작업의 백업은 `<configDir>/plugins/anki-card-manager/trigger-backups/`에 남습니다. JSON에는 노트 전체 내용이 포함되고 자동 삭제하지 않으므로 개인 Vault 백업처럼 관리하십시오. 플러그인을 설치하거나 업데이트하기만 해서는 전체 Vault 치환이 실행되지 않습니다.

## 개인정보, 네트워크 및 플랫폼 지원

플러그인은 로컬에서만 동작하며 네트워크 요청과 텔레메트리를 사용하지 않습니다. 현재 Vault 안의 Markdown 파일, 플러그인 설정, 트리거·배치 변경 백업만 읽거나 쓰며 Vault 밖 파일은 읽지 않습니다. 설정은 플러그인 폴더의 `data.json`에 저장하고, 변경 백업에는 영향받는 노트 내용이 포함됩니다. 재생성 가능한 카드 projection은 브라우저 IndexedDB에 로컬 저장하며 원본이 아닙니다. Markdown이 항상 기준이고, 영속 브라우저 저장소를 사용할 수 없으면 현재 세션에서 메모리 색인으로 전환합니다.

`isDesktopOnly`는 `false`입니다. 편집기 카드 UI와 반응형 관리 화면은 Obsidian API와 브라우저 호환 코드로 구현되어 데스크톱과 모바일에서 사용할 수 있습니다.

## 설치

### 수동 설치

1. 일치하는 GitHub Release에서 `main.js`, `manifest.json`, `styles.css`를 내려받습니다.
2. 세 파일을 `<Vault>/.obsidian/plugins/anki-card-manager/`에 복사합니다.
3. Obsidian을 다시 불러온 뒤 **Settings → Community plugins**에서 **Anki Card Manager**를 활성화합니다.

Obsidian Community Plugin Directory 등록이 승인된 이후에는 Community Plugins 화면에서도 설치할 수 있습니다.

## 개발

Node.js 22.13 이상 또는 더 최신 LTS 버전을 사용합니다.

```bash
npm install
npm run lint
npm test
npm run build
```

프로덕션 릴리스 파일은 저장소 루트에 생성됩니다.

`npm test`는 파서 테스트와 실제 CodeMirror DOM 회귀 테스트를 6.38.6 및 6.43.9 버전에서 실행합니다. 최초 렌더링, 위치 251, 포커스 진입·이탈, 펼침 후 높이 측정, 원문 편집, 두 배치 모드, 대규모 카드의 제한된 청크, 파싱 캐시 재사용, 답변 지연 렌더링, 연속 카드 묶음, 말줄임, Cloze 가리개·초기화·원문 보존, 자동완성 경계, 키보드/네이티브 삭제 보호, 반복 편집 및 확장 해제를 검증합니다. Obsidian 호스트 API는 테스트 대역을 사용하므로 Obsidian 앱 내부 확인을 대체하지는 않습니다.

관리 페이지 테스트는 IndexedDB 영속 저장·재개, warm cache 표시, 파일 단위 생성·수정·이름 변경·삭제 반영, 전체 재구축 확인·진행률, 메모리 fallback, 100행 페이지, 큰 그룹 지연 생성, 필수 열, 덱·태그 구분, 속성·유형 검색, 포커스·커서·IME 유지, 그룹 선택·전체 접기/펼치기·초기화, 유형 편집, 확인 창의 영향 범위, YAML·본문 보존, 중복 대상 보호, 오래된 원문 사전 검사, 부분 실패 안내도 검증합니다. 샘플링 테스트는 시각 시드 변화, 명시한 시드의 안정성, Count/Rate 경계, 정수 할당, 그룹 부족·중복, 고유 카드 처리, 오류 시 선택 보존을 검증합니다.

추가 회귀 테스트는 유형 메뉴와 편집기 등록 전환, Cloze 표기 해제, 모든 관련 기능의 사용자 지정 트리거, 설정 임시 입력, 동시 리터럴 치환, 영속 백업, 파일·설정 저장 실패, 동시 편집 보호, 재시작 후 복구를 검증합니다. 카드 유형·구분자·아이콘 연결은 `src/cardTypes.ts`에 모아 후속 유형을 확장할 수 있도록 합니다.

원본/Live Preview 전환, 읽기 화면의 구간 경계·수명 관리·화면 근처 청크 렌더링, 위쪽 방향키의 하단 진입, 원문 이동·반복 실행·각주, 배치 확인·복구, 독립 그룹 샘플링, 쉼표·전체 AND/OR 검색, 편집 창 원본 이동도 회귀 검증합니다. 실제 Vault 노트가 아닌 샘플 문서만 사용합니다.

브라우저 레이아웃은 `npm run test:browser` 실행 후 출력되는 편집기, `/manager`, `/manager-responsive`, `/reading` 주소에서 확인할 수 있습니다. 관리 화면 테스트는 좁은 패널 및 320/390/640/1024px 화면 폭을 지원합니다. 테스트 화면은 샘플 텍스트만 사용하며 Vault 파일을 읽거나 쓰지 않습니다. CodeMirror와 테스트 의존성은 프로덕션 플러그인에 포함되지 않으며, 실제 편집기 런타임은 Obsidian에서 제공합니다.
